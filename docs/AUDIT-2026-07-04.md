## 2. Bugs Found

### 🔴 BUG-1 — The "Submit Resignation" screen crashes
- **Where:** Profile → **Exit tab**, the "Submit Resignation" box.
- **What the user sees:** the section fails to render (blank/error) whenever an employee
  who hasn't yet resigned opens that tab.
- **Cause:** `src/pages/employee/ProfilePage.jsx` uses `FONTS.display` (lines ~762 & ~785)
  but never imports `FONTS`. It's a `ReferenceError` the moment that block renders.
- **Fix:** add `FONTS` to the existing constants import at the top of the file
  (`FONTS` is already exported from `src/lib/constants.js:42`). One line.
- **Why tests didn't catch it:** there are no component-render tests for pages, so a
  missing import only surfaces at runtime.

### 🔴 BUG-2 — Approving/rejecting leave from the **HR Dashboard** shows a scary error (but actually worked)
- **Where:** HR Dashboard → pending-leave list → Approve/Reject.
- **What HR sees:** a popup **"Error: sendLeaveDecisionEmail is not defined"**, which makes
  it look like the decision failed. In reality the leave **was** approved/rejected, the
  employee **did** get the in-app notification — only the email step blew up.
- **Cause:** `src/pages/hr/HRDashboardPage.jsx:177` calls `sendLeaveDecisionEmail(...)`
  but never imports it. The reference throws, and the surrounding `try/catch` turns it
  into that misleading alert.
- **Fix:** add `import { sendLeaveDecisionEmail } from '../../lib/email.notifications'`.
  The call itself already uses the correct arguments, so the import is the whole fix.

### 🟠 BUG-3 — Leave-decision **emails never actually send** (anywhere)
- **What the employee experiences:** they never get an email when their leave is
  approved/rejected — only the in-app bell notification.
- **Cause:** the *only* place that even tries to email is the HR Dashboard call site above
  (which crashes). The **main** place HR processes leave —
  `src/pages/hr/HRLeaveManagementPage.jsx` — sends the in-app notification but **never
  calls the email function at all**.
- **Fix / decision needed:** once BUG-2's import is fixed the Dashboard path will email
  correctly. We should **also** wire the same `sendLeaveDecisionEmail(...)` call into
  `HRLeaveManagementPage`'s approve/reject handler so employees get emailed no matter which
  screen HR uses. (Depends on MSG91 email domain being verified — already on the pending list.)

### 🟠 BUG-4 — A test gives false confidence on exactly the above
- **Where:** `src/tests/api.announcements.test.js` (lines ~32–40) — misfiled; it's testing
  `sendLeaveDecisionEmail`, which has nothing to do with announcements.
- **The problem:** it calls the function with the **wrong signature**
  (`{ email, full_name }, 'approved'`) versus the real one
  (`{ toEmail, toName, status, leaveType, fromDate, toDate, days }`), and it only checks
  that a **mock** was called — so it passes while testing nothing real. This is why BUG-2/3
  slipped through.
- **Fix:** move it to its own `email.notifications.test.js` and assert on the actual
  payload the real function builds (real behavior, not the mock).

### 🟡 BUG-5 — Birthday check can be a day off near midnight / New Year
- **Where:** `src/lib/api.notifications.js` `runDailyChecks` — the birthday date is built from
  **local** `getFullYear/getMonth/getDate` but compared against a **UTC** "today" string.
- **Impact:** low. In IST it only disagrees between 00:00–05:30, and only matters exactly on
  a birthday boundary. Worth tidying to one timezone convention while we're in there.

### ℹ️ Not bugs (checked and cleared)
- The 3 lint "cannot access variable before it is declared" hits
  (`TeamDirectoryPage:220`, `EmployeeManagementPage:667`, `TwoFactorAuth:19`) are all the
  `useEffect(() => { load() }, [])` pattern — safe at runtime, **false positives**.
- `'clients' is not defined` in `public/sw.js` is a service-worker global — **false positive**.
- No single-recipient ("`list[0]`") notification bugs found — that past bug-class is holding.

## 3. "Make It Smarter" Opportunities (by feature)

### Automated reminders (birthdays, holidays, monthly regularization)
- **Today:** they run **only when an HR/Admin happens to load a page** (`runDailyChecks`).
  If no admin logs in on someone's birthday, or over a weekend, the reminder just doesn't fire.
  It also runs an **N+1 query** (one lookup per employee) on every such page load.
- **Smarter:** move these to a **scheduled job** (Supabase pg_cron / a scheduled Edge Function)
  that runs once a day regardless of who's logged in, and batch the duplicate-check into one
  query. More reliable, and faster page loads for HR.

### Leave
- **Blocking clarity:** we already block over-balance paid requests upfront — good. Smarter
  next step: show the **remaining balance live** next to the date picker as they choose dates,
  so they see "3 of 12 left" before hitting submit.
- **Half-day + unpaid combined:** worth confirming the math when someone marks a request both
  half-day *and* unpaid (edge case) — quick review, not a known bug.

### Manager Transfers (just shipped)
- **Bulk promote / reassign:** you already hit this — promoting one person to manage several
  reports means editing each report one-by-one. A "Set as manager for… (multi-select)" action
  on an employee's row would make reshuffles one step. (Flagged as a follow-up task.)
- **Pending-request visibility:** on the Team Directory card, show a small "transfer pending"
  badge so a manager doesn't start a second request or wonder where someone went.

### Attendance
- **Regularization reminders** share the same "only runs on page load" fragility as above —
  same scheduled-job fix applies.
- **Weekly-hours widget** is a nice touch; a small "vs. last week" delta would make it smarter
  with almost no extra data.

### Employee Management / Onboarding
- **Manager dropdown** was just widened to all active employees (good). Smarter: sort/group it
  (e.g. by department) so picking the right manager in a big list is faster.
- **Offboarding + manager_id:** when someone is deactivated, their former reports keep pointing
  at them in the data (we now hide inactive managers at read time, which is correct). Smarter:
  at deactivation, **prompt HR** "this person manages N people — reassign them now?" so the org
  chart never silently dangles.

### Notifications
- **In-app is solid; email is half-wired** (BUG-3). Deciding "which events should email vs.
  in-app only" as an explicit list would make the whole system feel intentional rather than
  ad-hoc. Candidates for email: leave decision, welcome, resignation acknowledgement.

### Code health (cross-cutting)
- **Lint is currently noisy** (99 mostly-unused-var errors), which means real problems hide in
  the noise (that's partly how BUG-1/2 lived undetected). A one-time cleanup + keeping lint at
  zero would turn it back into an early-warning system. Low effort, high leverage.
